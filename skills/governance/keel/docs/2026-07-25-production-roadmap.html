How this plan was produced

Six parallel audits over the real tree — install UX, engine coverage, security, self-grounding, product coherence, repo hygiene — each required to ground every finding in a file:line it opened or a command it ran. The security dimension additionally proved its headline finding end-to-end against the real entrypoint.

The four highest-stakes claims were then re-verified by hand rather than taken on trust: the .env mechanism (benign payload, no exfiltration), branch-protection state (gh api, 404 + empty rulesets), the deployed named participant pages (git ls-files), and the probe verdict census (grep over all 30 minted files). Each is cited at its unit below.

Method caveat, stated because this repo is about honest measurement. A first fan-out lost six of seven agents to connection drops and stalls; only the security dimension survived. The five re-run dimensions completed. Findings that were not independently re-verified by hand are marked [unverified] below and should be treated as leads, not facts.

P0 — blocks any public push

U1 · Stop reading security-critical config from the ambient environment blocker

A .env file in the repository being measured takes control of Keel's two most security-critical settings. Bun auto-loads .env from the process cwd, and during a normal run the cwd is the target repo — that is what README.md and SKILL.md tell users to do.

  • probe-sandbox.ts:186 — if (process.env.KEEL_SANDBOX === '0') returns unconfined.
  • probe-sandbox.ts:339 — process.env.KEEL_PROBE_DIR ?? ~/.config/keel/probes.
  • probe-sandbox.ts:172 — sanitizedEnv forwards every KEEL_* var except the two internal ones, so both travel into the child.
  • classify.ts:350 — child spawned with env: process.env; the parent's environment is already poisoned.

Loading a probe executes it, so this is code execution as the invoking user — including on macOS, the one platform where the seatbelt would otherwise apply. ${PWD} expansion makes the payload self-contained: no absolute paths, no user opt-in.

Verified by hand. A directory containing only a .env with KEEL_SANDBOX=0 and KEEL_PROBE_DIR=${PWD}/.keel-probes yields sandboxed: false | reason: KEEL_SANDBOX=0 and a probe search path including the attacker-controlled directory.

The mitigation pattern already exists in-tree. corpus.ts:529 runs classify with run(args, REPO_ROOT) — cwd pinned away from the target — and passes --probe-dir explicitly, which wins in resolveProbeDirs (flagDirs.length ? flagDirs : [...]). The corpus run over 15 third-party repos was never exposed. Generalize that.

Note the asymmetry: --probe-dir overrides its env var; nothing overrides KEEL_SANDBOX — it is read unconditionally before any flag is consulted.

Do: delete KEEL_SANDBOX as an input entirely (--no-sandbox already exists at probe-sandbox.ts:541 and is the honest spelling); honour KEEL_PROBE_DIR only as a flag; pin every user-invocable entrypoint's own cwd to SKILL_ROOT so Bun never auto-loads target dotfiles.

Acceptance: a fixture target carrying a hostile .env plus a marker-writing probe, run through classify.ts from inside that directory, leaves no marker file. The filesystem decides the exit code — anchored under Keel's own rubric.

U2 · Platform-qualify the confinement claim blocker

SKILL.md:90 states without qualification that probes run "only inside a sandboxed child process." probe-sandbox.ts:189 returns unconfined on any non-darwin platform. On Linux and Windows the child is a child process and nothing more.

The engineering is honest everywhere it isn't shipped: probe-sandbox.ts:46-72 documents the degradation precisely, tests/probe-sandbox.test.ts:227 writes down the platform gap, and test.yml runs a macOS leg specifically so the confinement proof executes somewhere. The gap is between what the code knows and what the docs say.

Do: qualify SKILL.md's sentence; add a platform table to SECURITY.md §"What Keel does on your machine"; scope README's "Nothing is transmitted anywhere" to Keel itself and note that probes are executed code. All three are orchestrator-owned, so these land as a proposed diff.

U3 · Make test.yml a gate blocker

Its own header states the requirement — "a non-zero exit must block the merge." Verified: gh api repos/broomva/keel/branches/main/protection → 404 "Branch not protected"; rulesets → []. The fix Keel prescribed for itself landed as a workflow file, not as a gate. That is exactly grounding-classes.md:37's "looks anchored and is not."

Do: a ruleset on main requiring test (ubuntu-latest) and test (macos-latest), plus require-a-pull-request. Both legs — the macOS leg is what makes the confinement claim an executed one, and requiring only ubuntu lets it go red unnoticed.

U4 · Consolidate repo identity resolved 2026-08-03

At the time of writing, Keel lived in two repositories at once and neither was unambiguously canonical: PR history accumulated in one, while the repo that npx skills add actually installed was a push mirror with none of it. The plan below was to pick one and freeze the other.

What happened instead: both were retired. Keel now lives at skills/governance/keel/ in broomva/skills, installs via npx skills add broomva/skills --skill keel, and has exactly one origin, one PR flow, and one CI lane. The ambiguity this item tracked cannot recur, so nothing here is scheduled.

U6 · Make the skill runnable by a stranger's agent blocker

grep -n "scripts/" skills/keel/SKILL.md returns nothing. The 235-line contract the installed agent reads names none of the nine scripts it ships. An agent that reads it does the most likely thing: performs gather and classify by hand with Read/Grep, never invoking the probe library, never spawning the sandbox, reasoning over summaries rather than literal raw — which SKILL.md:78 explicitly forbids. The tool degrades into a prompt and the failure is invisible, because the output still looks like a Keel report.

There is also a real gap in the pipeline: classify.ts emits {decided, pending, warnings}; render.ts and route.ts consume a Report. Nothing shipped bridges them. The agent must hand-author JSON against a 260-line frozen schema with no template, no example, and no validator.

Do: add a ## Run it section to SKILL.md with the literal command sequence and file handoffs; ship scripts/assemble.ts that merges nodes + verdicts, refuses on any node without a verdict (naming ids), and computes groundingRatio from the schema. That is plumbing — it classifies nothing — so it respects the invariant. Also state Bun as a hard runtime requirement (README:109 currently calls it a dev-time concern) and add a preflight that says so instead of emitting a Node module-loader stack trace.

U7 · Cut v0.1.0 blocker

There is no version string anywhere in the shipped artifact. npx skills add broomva/keel resolves to whatever the default branch is at that instant. Nobody can audit a version, pin a version, or say "I reviewed the probe library at X" — which is precisely the review the compounding story depends on.

P1 — the numbers must describe the repository

U8 · Re-measure Keel at HEAD, uncapped

The most-quoted number about Keel measures a repository state that stopped existing 21 commits ago, and the prose beside it asserts a present-tense fact the tree contradicts. reports/keel.json is at 44f7e8d6; at that revision .github/workflows/test.yml did not exist — which is exactly what the 0.357 diagnosed. The fix landed in 8bb1614.

Two compounding distortions: the 0.357 was computed over a capped 25 of 32 nodes, and gather at HEAD now produces 43. [unverified] The audit projects roughly 0.625 uncapped.

Do: re-run uncapped, commit, republish, and write the two-state sentence the repo actually earned — "measured 0.357 at 44f7e8d6; its test suite ran in no CI, so it gated nothing. It scores N at <rev>; the gap is the fix." That is a better story than a frozen 0.357, and it is true.

U9 · A drift check, not a scored run, in CI

Keel cannot honestly score itself in CI, and should not pretend to. Classification is agentic; CI has no agent. A probe-only run would decide ~0 of 43 nodes and publishing a ratio over the remainder is the shoppable move under a different name. An agent job can produce the ratio but must never be a required check — an agent of the same class as the authors deciding whether the authors' repo is grounded is grounding-classes.md:26's own example of self-referential verification.

Do: (a) a deterministic gather-set drift check — re-gather at HEAD, fail if the node-id set differs from the committed report, with a message saying re-measure or update the baseline deliberately. It proves coverage is current, not that any verdict is, and must say so. It would fail today at 25 vs 43, which is the correct signal. (b) a scheduled agent job that opens a PR with a refreshed report, labelled "agent-judged, same-class reviewer," never a gate. (c) a revision + date stamp beside every published ratio, so staleness is visible with no check at all.

U10 · Declared vs effective node cap

corpus.ts:968 computes the effective cap (opts.cap ?? nodeCap) but :1358 and :1530 write the declared value into the summary. reports/corpus-summary.json says nodeCap: 40; every entry sampled 25. In a file whose header reads "NO SILENT ANYTHING," the machine-readable provenance contradicts the prose. Fix, plus a regression test.

U11 · Disclose gatherer blindness [unverified]

When Keel cannot see a repo's CI system, the result is byte-identical to a repo with no CI: it reports a ratio over whatever residue it could read — typically package.json scripts and Makefile targets, which skew ungrounded. A Jenkins shop would publish a near-zero ratio for a repo whose real verification is an anchored runner exit code.

schemas/keel.ts:233-248 already names this as Keel's own shoppable class: "surfaces the gatherer cannot read are silently absent rather than unknown." The schema's warning is not honoured in code.

Do: emit a list of unread candidate surfaces beside nodes — a recognise-but-cannot-parse list (Jenkinsfile, azure-pipelines.yml, .buildkite/, .drone.yml, …). Purely mechanical, no judgment, so the plumbing invariant holds. Then publish a ## Coverage section enumerating what is supported.

U12 · Publish the anonymized cohort dropped 2026-08-03

This item covered a set of named third-party repositories that had been scored and published as a deployed page, and the privacy problem that creates: the two lowest scores were dominated by unknown, which under Keel's own fail-closed rule means "could not trace," not "does not test." A reader seeing a handle beside a 0.0 will not make that distinction.

What happened instead: the published site was not carried into the monorepo, and neither were the per-participant reports or the raw cohort JSON. There is nothing left to anonymize. The reasoning is kept because the hazard it names — a fail-closed unknown reading as an indictment when attached to someone's name — applies to any future published measurement of a repository Keel does not own.

P2 — the probe library

The library as it stands is biased toward the shoppable class, 18:1. Census over all 30 minted files: 18 not_a_check, 11 anchored, 1 self_referential. Every not_a_check removes a node from the denominator, so library growth mechanically pushes measured ratios up — Keel's own named failure mode, produced by its own crystallization machinery, invisible because probe verdicts are cheap.

The audit demonstrated it: four hand-written CI nodes, including pip install -e . && python -m pytest tests/, all came back not_a_check by probe. tests/probe-loader.test.ts:209 already states the intended invariant — the one shipped probe is self_referential and can only lower a ratio. The minted library inverts that property.

Decision taken: ship all 30, after narrowing. That raises the review bar rather than lowering it — every one of the 18 must earn its class before it ships.

ATTEMPTED 2026-07-25, AND REVERTED. The premise did not survive contact. All 30 were promoted with a structural whole-body guard, fixtures and a bias test; adversarial review then found three defects, each reproduced by hand before this was written. The library is not shippable in its current state, and the guard as written made things worse. The archive at docs/probes-as-minted/ is what landed instead.

What the attempt established — start the next pass here

B1 · Ten probes ship other repositories' file:line as evidence. chat-webhook-notification emits vercel-ai's .github/workflows/slack-workflow-failure-notification.yml:20-29; the conftest probe emits anthropic-quickstarts' path. evidence is rendered into the report (render.ts:753), so a user auditing their own repo gets citations to files they do not have. This is the same sin the probe headers sermonize about — kept out of the tokens by rejectRepoLiterals(), smuggled back in through the payload. Disqualifying on its own, and it is a defect in the minted library, not in the promotion.

B2 · curl is a whole-body token. chat-webhook-notification's ASSERT_ANY is ["curl","uses:","webhook"]. A curl --fail healthcheck — the canonical anchored signal — therefore reads as "all provisioning" and can be filed not_a_check. Two steps with byte-identical run: bodies got different verdicts based on the step's name.

B3 · The guard is a category error on uses: steps. It splits a body on &&/;/|| and requires every part to match the probe's tokens — but gather.ts emits YAML with: keys, TOML table rows and Rakefile bodies inside raw. Measured: actions/setup-python@v5 carrying two with: keys went from not_a_check (correct) to abstaining. ci-provisioning-action alone lost 14 decisions.

The corpus A/B, over 327 nodes: decisions 145 → 121; not_a_check 120 → 93. Twenty-seven fewer shoppable-class decisions, bought by breaking provisioning detection. Abstention is the safe direction and the trade might still be worth making — but not with B3 as the mechanism.

B4 · The bias test measured the wrong thing. It counted probe files (18/10/2). Decision-weighted over the corpus, the shipped set is 108 not_a_check / 29 anchored / 3 self_referential — 77% of all probe decisions leave the denominator, and ci-provisioning-action is 56 of them on its own. A file count cannot see that, and it is the number that actually describes the bias.

B5 · Dispatch is first-match-wins in load order (probe-sandbox.ts:551) with no specificity tie-break, so a broad not_a_check probe gets first refusal on nodes an anchored probe would have claimed. Ordering, not judgment, decides.

Revised sequence

  1. Strip the payload literals first (B1) — mechanical, and it blocks everything else.
  2. Re-derive the guard from run: bodies only (B3): apply it when the step has a shell chain, never to a uses: step or a config-file node. Then re-run the 327-node A/B and require decisions not to fall.
  3. Audit the token sets for assertion-surface commands (B2) — curl, make, bash, any bare script invocation may not serve as a whole-body provisioning token.
  4. Make the bias test decision-weighted (B4) over a committed corpus node set, and add per-probe fire counts.
  5. Then promote, in a reviewed subset, smallest-blast-radius first.
  6. One shared guard helper, not 17 copies. Fixing a copy-pasted guard means 17 new versioned files.

And the ε-audit (U19) should land before the library grows, not after. Promoting 18 probes into the shoppable class while the counter-metric that would detect their drift exists only as prose is the wrong order — the corpus run already demonstrated that a cheap wrong verdict is invisible precisely because it is cheap.

U13 · Fixture harness first

No mechanism currently tests a probe. CONTRIBUTING calls a probe "the highest-value contribution" and says probes are "diffable, testable, and rejectable," but a PR adding one would be gated by nothing — and would fail tsc unless the contributor hand-applies the type annotations the mint header describes.

Do: tests/probes/<id>.fixtures.json — an array of {node, expect: 'anchored'|'self_referential'|'not_a_check'|null} — plus one tests/probe-library.test.ts that enumerates skills/keel/probes/*.ts, loads them through the real sandbox, and runs every fixture. Executed assertion over real files: anchored by Keel's own definition.

U14 · The compound-command abstention rule

A step is provisioning only if provisioning is all it does. Every not_a_check probe must abstain when node.raw carries a command separator (&&, ;, |) or a second non-blank command line. Abstention falls through to the agent, which is the safe direction.

failure-suppressed-edge needs a class change, not narrowing. A suppressed test step is a check that cannot fail. Filing it not_a_check deletes it from the denominator instead of counting against the score — it is the single clearest instance of the shoppable-class failure in the library. The honest verdict is self_referential, or abstention. Narrowing its match would leave the defect intact on every node it still matches.

U15 · The still-live drift

The one documented instance of probe drift was fixed on the wrong axis. unfrozen-dependency-install over-matched because an install token appeared inside a multi-line block that also ran a real check; the narrowing addressed lockfile-freeze flags instead. A step that literally invokes pytest is still classified not_a_check by it today. [unverified — audit finding]

It was also edited in place at v1 rather than minted as v2, defeating the loader's version-shadowing audit trail. Mint v2, re-run the tiktoken repeat, and confirm the two swallowed nodes come back as pending for you: 2. Make in-place editing of a minted probe a rejected practice in CONTRIBUTING.

U16 · Promote, with a bias test

Add the type import and : Probe annotation to each (they resolve inside the repo), fixtures for each, then ship. Add a library-level test asserting the shipped set's verdict distribution is not overwhelmingly denominator-shrinking, in the spirit of probe-loader.test.ts:209 — the guard that makes the 18:1 problem impossible to reintroduce silently.

Also: the 30 currently live only in .keel-probes-corpus/, matched by .gitignore's .keel-probes-*/ — a fan-out worktree-isolation rule from 00-orchestration.md:104 that swept up the corpus library too. They are one rm -rf from gone. Archive all 30 under docs/ as the corpus-run record regardless of which ship.

P3 — product

U17 · corpus-agentic — the next unit decided

The corpus never contained the market. 13 of 14 measured targets are human-maintained OSS, measured under a banner reading "your agents are grading their own homework." The saturation is a denominator problem, and the only entry with a populated denominator is the only agent-built one: Keel's own 0.357 carries 9 self_referential; the other 13 targets carry 5 between them.

Deliverable: reports/corpus-agentic-summary.json plus five per-target reports, via corpus.ts against a new pinned corpus file. Engine and probe library unchanged.

Selection predicate, committed before any repo is measured so it cannot be shopped after the fact: a target qualifies if >50% of its last 200 commits carry an agent trailer (Co-Authored-By: Claude|Devin|Codex|Cursor). Mechanically checkable from git log — the selection criterion is itself anchored.

Acceptance: ≥5 targets at status ok, each with its denominator and distinct-source-file count printed beside its ratio, and one stated sentence answering how many scored exactly 1.000 and whether the pooled agentic ratio differs from 0.853 by more than 0.10.

Why first: it costs one corpus run and no schema risk. If agent-maintained repos land near 0.357, the pitch gets its evidence and oracle-axis scoring becomes a refinement rather than a rescue. If they saturate too, the case for the re-freeze is proven from data instead of asserted from 41 arguments.

U18 · Independence as a vector, not a second boolean schema re-freeze

The handoff's 41/122 oracle claim verifies — an independent recount over all 122 anchored verdicts returned 40 strict / 41 inclusive (32.8–33.6%), reproducing corpus-summary.json exactly.

But the corpus wrote down a second admission axis the proposal missed: 31 further verdicts admit the check's scope — select lists, exclude lists, thresholds, exemptions — is authored inside the write boundary. mcp-python-sdk: "the threshold was raised from the default 10 to 24, so the enforced bar is set inside the write boundary even though the measurement is not." Keel on itself: "moving a file under docs/handoffs/ suppresses the signal without touching the scanner."

Union: 68 of 122 (56%) carry a written admission that something load-bearing sits inside the boundary. Oracle-axis alone captures 60% of what the corpus already said.

So if a re-freeze is spent, spend it once: writeBoundary.independence?: { execution, oracle, scope }, each boolean|null, each failing closed on null, with a per-axis ratio beside the existing one. Additive, so existing consumers stay valid. Gated on U17 reporting.

U19 · The ε-audit script (W2·F)

First on the degradation ladder, and the mechanism was exercised by hand — it caught real drift. What is missing is the loop: a sampled, scheduled, agent-blind re-decision across all deciders. The schema already carries Verdict.audit, so no re-freeze is needed.

It has two dependents. It is what makes "and it audits itself" true rather than aspirational (U5), and constructive-grounding-layer.md:141 makes it a hard prerequisite for Phase 3 while asserting it "was built" — that line needs correcting to "specified but not built."

Explicitly not next

  • Constructive Phases 2–4. The handoff's own verdict: 2 routable / 18 unroutable says routing is bounded — most fixes need a human decision, not a wire. Phase 2's justification cites a SKILL.md claim that has since been deleted; Phase 3 is blocked on U19; Phase 4's answer key is real but costs a gatherer rewrite ("extraction over prose, not YAML").
  • A gatherer rewrite for granularity. Granularity inflates the numerator (122 anchored collapse to 59 under file-dedup) but explains none of the saturation, which is caused by an empty non-anchored column. Ship the disclosure — "anchored 15 across 4 files" — not the rewrite.

Carried forward, not scheduled

  • Test coverage. corpus.ts (1,701 lines) and curve.ts (1,665) have no direct test — the two files that produced the published corpus table and the crystallization curve. [unverified: ~48.6% of shipped script LOC untested]
  • corpus.ts ships but cannot run outside this repo — it needs a corpus.json workspace. Move it to root scripts/ (already outside the packaging boundary) or guard its entry.
  • Windows path handling — workflow path regexes cannot match, so every CI step silently disappears. WSL is unaffected, which is likely why it has not surfaced.
  • Sampling is kind-diverse round-robin, which is right for probe minting and wrong for estimating a ratio. Either sample proportionally or state plainly that a capped number is a kind-balanced sample, not a population estimate.
  • Supply chain in Keel's own gates — l3-stability.yml:44 clones and executes a script from a mutable third-party HEAD inside a job holding pull-requests: write, and every Action floats on a mutable major tag.
  • The seatbelt's credential denylist misses ~/.npmrc, ~/.git-credentials, ~/.docker, ~/.kube, and probe evidence strings are an unbounded egress channel into published HTML.
  • Report has no warnings field, so a degraded (unconfined) run is byte-indistinguishable from a confined one in the published artifact.

Keel measures the shape of verification, not its quality. A repo can be 100% anchored with terrible tests. Anchoring says the signal comes from outside; it does not say the signal is enough.
