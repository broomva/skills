Make temporal drift visible.

An opt-in lint pass catches stale dates and undated mutable-state claims without claiming to understand belief revision.

Cross-Review: 10 / 10 331 Bookkeeping tests pass locally on Python 3.12. The CI matrix verifies Python 3.11 and 3.12; default lint behavior is unchanged.

The failure was not missing memory. It was stale memory presented as current.

Contradiction theater

Entity prose described required temporal fields and promotion-time reconciliation that no producer, schema, or linter actually implemented.

State drift

Chronos marked milestones shipped, then retained the same choices under “Open follow-ups.” Other entities carried body evidence newer than frontmatter.

False confidence

The ordinary linter correctly validates structure, but it caught none of these temporal defects. Readers could not distinguish an old snapshot from a live claim.

A deliberately narrow warning path

Entity Markdown
updated metadata, dated evidence, visible state labels
→
Bounded checks
date ordering + explicit mutable surfaces
→
Warnings
temporal_updated or temporal_as_of; never a hard failure

The architectural boundary: this pass recognizes inspectable syntax. It does not infer that one belief supersedes another, reconcile contradictions, require revision links, or silently mutate entities.

Compatibility is the contract

Default: bookkeeping lint

  • Byte-for-byte existing behavior
  • Existing severities and exit codes
  • No new temporal scan

Opt in: bookkeeping lint --temporal

  • Only warning severity
  • Ignores invalid and future evidence dates
  • Audits claims, precise headings, and explicit labels—not arbitrary present-tense prose
