Specification · BRO-2262

The Parallax UI layer

Dashboard, generative UI and world-model rendering are not three products. They are three projections of one object that the runtime already computes — and the only genuinely new design is the vocabulary between them.

2026-08-23 base d4ffd39 status: proposed surface 1 of 3: Run Theatre

§1The thesis

Parallax's core is six operators over an event log. Two of them are the entire UI story, and both were written for other reasons:

observe(world, log, branch) → State     // state is a FOLD over the log
score(trajectory, objective) → Score    // carries Origin, not just a number

Because observe is a pure fold, the state at step n is not something to cache, snapshot or diff — it is observe applied to the first n events. Time-travel is already implemented. Every mechanism a conventional debugger UI spends a quarter building is a consequence of a decision made in skills/simulation/parallax/runtime/src/core/ops.ts for reasons that had nothing to do with pixels.

And Origin is a two-element lattice with a meet (skills/simulation/parallax/runtime/src/core/provenance.ts:29): any simulated input drags the result to simulated. So provenance propagates through composition without a propagation engine.

The UI layer therefore computes nothing. Its whole job is to be a faithful projection of a data model that is already time-indexed, already typed, and already provenance-tracked. Every design decision below follows from taking that seriously.

§3The contract: a Frame the renderer cannot forge

DESIGN.md closes with three prohibitions, quoted here because they are the requirement:

DESIGN.md — what this design must never do
  1. Present a simulated value with the same weight as an observed one.
  2. Render a claim inside generated pixels.
  3. Publish a figure whose provenance is not on the page next to it.

Today all three are conventions. Any component can render <div>{47}</div> and nothing objects. That holds while a careful author writes every surface by hand. It does not survive a generative layer, and it does not survive a second contributor.

So make it structural, using the mechanism this codebase already trusts — the brand symbol that guards ActiveOntology:

// skills/simulation/parallax/runtime/src/view/frame.ts
const FRAME: unique symbol = Symbol("parallax.frame");

export interface Cell {
  readonly slot: string;            // "state.apps_count"
  readonly value: unknown;
  readonly origin: Origin;           // observed | simulated
  readonly klass: Klass;             // PINNED | STABLE | RECORDED
  readonly evidence: string | null;  // what it was read from — NULL if nothing
  readonly unit: string | null;      // from ActionSpec.units
}

export interface Frame {
  readonly [FRAME]: true;
  readonly seq: number;
  readonly branch: string;
  readonly cells: readonly Cell[];
  readonly violations: readonly Violation[];
  readonly traceHash: string;
}

// The only constructor. Minted in core, from the log, never by a renderer.
export function frames(world: TypeRecord, log: EventLog, branch: string): readonly Frame[];

The renderer's component vocabulary accepts Cell references only, never literals. A component that wants to display a number must be handed a Cell, and a Cell carries its own origin, evidence and unit as one indivisible object.

That converts the three prohibitions from rules into properties:

ProhibitionEnforced by
Simulated never weighted as observedorigin is on the same object as value; a renderer cannot receive one without the other
No claim inside generated pixelsThe model emits {component, slot} pairs; a literal in a value position fails validation
No figure without its provenanceevidence travels with value. Rendering the value without it requires deliberately discarding a field

A Cell whose evidence is null is not an error — it is a value nobody claimed to have read from anywhere, and it must render differently. §7.1 is the case that makes this urgent.

The chosen first surface. It is the smallest diff with the largest payoff, because the drawing already exists.

4.1 The figure

4.2 Why the page can be static and still scrub

The artifact route is self-contained HTML with no server behind it. The obvious implementation — ship the event log and re-fold in the browser — is wrong, and instructively so. It would require reimplementing step and observe in client JavaScript: a second implementation of the transition function, able to disagree with the first. This product exists to refuse exactly that class of divergence.

So: pre-compute every frame at render time. A run of horizon N emits N+1 frames, folded in Bun by the same observe the runtime uses, and embedded in the page. The client does one thing:

scrub.oninput = () => paint(FRAMES[scrub.valueAsNumber]);   // an index, not a computation

The page cannot compute a state because it has no transition function. It can only display states the runtime already produced. Default horizon is 12, so this is thirteen frames — the cost is bytes, and bytes are the cheap resource here.

Consequence worth stating

With no JavaScript at all, the page must still render the final frame and the complete figure. DESIGN.md already requires this of motion — "the reduced path lands on the finished figure" — and pre-computation means honouring it costs nothing: the last frame is already in the document.

The governed-vs-ungoverned comparison is the product's central claim, and today it is delivered as two numbers in a receipt. Drawn, it becomes a single glance: one path reaches a violation marker, the other does not, and the shield is the only difference between them. run() already forks both branches (skills/simulation/parallax/runtime/src/tools/handlers.ts:880) — the data has been there the whole time with nothing to display it.

§5Surface 2 — the Ontology Map, and the acceptance problem

Rendering a proposal as HTML is not merely unbuilt; it is in tension with the gate. Acceptance binds a human to stored bytes. A second rendering is a second artifact they might accept — and if they read the HTML and clicked accept, they accepted the HTML. This is the same failure as a paraphrase, which is precisely why render re-sends byte-for-byte instead of re-summarising.

Resolution: make it a gate rather than a compromise.

  • The page embeds the byte-identical renderProposal output in a <pre>.
  • It displays sha256 of exactly those bytes beside the accept control.
  • Accepting posts {proposalId, textHash}.
  • Hash mismatch → typed refusal, PROPOSAL_TEXT_DRIFT, joining the other 46 codes.

The visual map can then never be what was accepted. The bytes are; the map is an index into them. An ambiguity becomes a code you can branch on, which is this system's house move.

What the map draws: the state vector as a field of cells, each carrying its evidence; actions as edges from actor to the slots they move; blocking questions as gates that visibly disable acceptance; and a missing conservation invariant drawn as a hole rather than a footnote. An ontology with no oracle should look wrong.

§6Surface 3 — the Workspace Instrument

6.1 The gap

agent-workspace has no proposer. It falls through to proposeFromDirectory (skills/simulation/parallax/runtime/src/core/ontology.ts:88-90) and differs from filesystem only in refusing --root. The context class most central to an agent-operated workspace reads a directory listing and stops.

6.2 Shell and filesystem as certified observers

The tempting version — pipe git status, test counts and line totals into a dashboard — produces exactly what Parallax exists to refuse: confident numbers with no provenance, displayed beside numbers that have it.

The correct version admits them to the event log, where the discipline already lives. An observer is a declared, replayable command bound to a slot:

{ slot: "apps_count", cmd: ["ls", "-1", "apps"], fold: "count", actor: "observer" }

It emits an Event with derivation: null — real, not model-derived — and a klass. And the machinery that decides whether to believe it already exists. certifyPolicy runs a policy repeatedly against a fixed probe and demotes it in code however it declares itself. Its docstring states the principle without qualification:

"A reproducibility class that a policy declares about itself is not evidence."

Point that same test at a shell command and the lattice CLASS = { PINNED: 2, STABLE: 1, RECORDED: 0 } sorts the workspace with no new judgement:

ObserverUnder repeated probeClassOrigin
ls -1 appsidenticalRECORDEDobserved
git rev-parse HEADidenticalRECORDEDobserved
date, uptime, curl …driftsdemotedsimulated

skills/simulation/parallax/runtime/src/core/ops.ts:200 already performs the mapping: origin = cert.effective === "RECORDED" ? "observed" : "simulated". The provenance layer needs no change whatsoever.

6.3 Two consequences

  1. It repairs §7.1 structurally. apps_count becomes an observed event from a declared command, or the slot does not exist. It can never again be a silent 0 wearing an evidence label.
  2. It gives the ontology an oracle. An agent workspace has genuinely conserved quantities a directory listing cannot see: commits are append-only, a ticket occupies exactly one status, a PR is open xor merged xor closed. Those are kind: "conservation" invariants — the free, non-gameable oracle the proposer asks for and currently never finds.

A closed component vocabulary — StateCell, TrajectoryPlot, EvidenceLine, OriginSplit, ViolationList, QuestionGate — each taking a slot id. The model emits a layout tree of {component, slot}; a validator rejects any literal in a value position.

Gate on this, per house discipline

The validator ships with a mutation test that rewrites one slot reference into a literal and asserts the render refuses. Without a mutation proof it is a convention wearing a type, and §7.2 is the standing evidence that an untested assertion in this repo can pin a defect as correct.

§10What this spec does not decide

  • Whether the Theatre ships live. The artifact route is static by choice. A live instrument over a running workspace needs a served runtime and an auth story; deferred, not rejected.
  • The observer registry's shape. §6.2 fixes the certification mechanism, not where observers are declared or who may add one. A shell command in a config file is an execution surface and needs its own threat model.
  • Whether RunValue should carry the trajectory. It exposes steps: number today (handlers.ts:802). The Theatre takes the trajectory from run()'s in-scope value, so nothing forces the change now.
  • Calibration. Unchanged and out of scope. Parallax publishes no accuracy number, and no surface here may imply one.
